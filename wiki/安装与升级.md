# 安装与升级

## 前置条件

- KernelSU 支持模块与 WebUI。已验证 KernelSU 3.3.1 late-load。
- AdGuard Home 已安装并运行，默认 DNS 监听端口为 `5591`。
- DNS 集成需要 Clash Meta 包名
  `com.github.metacubex.clash.meta`，且活动 profile 可读。
- 设备已有可用的安全模式、模块禁用或恢复入口。

模块入口只使用 `service.sh`，不依赖 `post-fs-data.sh` 或 `initrc`，因此可在
late-load 会话中手动启动。

## 安装步骤

1. 从 [Releases](https://github.com/deancyl/rmg-netguard/releases/latest) 下载
   `rmg-netguard-v2.2.1.zip`。
2. 在 KernelSU 管理器中刷入 zip。
3. 如果模块没有被当前会话加载，手动启动：

```sh
su -c 'sh /data/adb/modules/rmg_netguard/service.sh'
```

4. 打开 WebUI，先保持“只看不动”。
5. 检查 AGH 进程、5591、VPN 状态和过滤探针。
6. 网络正常后，再按需启用“自动切换”或“DNS 集成”。

## 安装后验收

```sh
su -c 'cat /data/adb/modules/rmg_netguard/run/state.json'
su -c 'sh /data/adb/modules/rmg_netguard/scripts/probe.sh'
su -c 'sh /data/adb/modules/rmg_netguard/scripts/rules_audit.sh'
```

检查项：

- `guard.pid` 指向的进程存在，且只有一个 guard。
- `state.json` 时间戳持续更新。
- `events.log` 没有重复的状态抖动。
- `observe` 下模块自身不新增 netfilter 链或 jump。
- 一键体检不会造成 DNS 中断。

## 从旧版本升级

直接刷入新 zip。以下运行数据会保留：

- `run/mode`
- `run/integration`
- `run/events.log`
- `run/backups/`

若升级前处于 `auto`，升级后仍保持 `auto`。因此升级前应确认 AGH 与 5591 健康，
并保留当前 profile 备份。

## 卸载与回滚

推荐在 KernelSU 管理器中卸载，或执行：

```sh
su -c 'ksud module uninstall rmg_netguard'
```

`uninstall.sh` 会：

1. 校验 cmdline 后停止 guard；
2. 还原模块持有的全部 Clash Meta profile 备份；
3. 若模块曾摘除 AGH 劫持，则重新插入跳转；
4. 清理模块 `run/` 数据。

紧急情况优先使用 KernelSU 安全模式或模块禁用入口，不要在未知状态下反复重启。

## 手动回退到只观测

WebUI 切到“只看不动”只会停止后续自动动作，不会额外改变当前网络拓扑。若需要
立即恢复 AGH 劫持，再使用 WebUI 的“恢复 AGH 劫持”，并在执行前确认 AGH 5591
已经响应。
