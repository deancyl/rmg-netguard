# 架构与工作模式

## 组件

| 组件 | 职责 |
|---|---|
| `guard.sh` | 周期采样、状态机、防抖和自动切换 |
| `controller.sh` | AGH 健康门控的 attach / detach |
| `config_toggle.sh` | Clash Meta profile 集成、备份、漂移检测 |
| `webui.sh` | WebUI 命令分发与退出码传播 |
| `probe.sh` | 只读网络与拓扑体检 |
| `rules_audit.sh` | 只读规则与 profile 风险审计 |

## 双轨拓扑

### 轨道 A

前提：VPN 关闭，AGH 劫持存在。

```text
App DNS :53
  -> nat OUTPUT
  -> ADGUARD_REDIRECT_DNS
  -> AGH :5591
  -> 上游 DNS
```

### 轨道 B

前提：VPN 开启，AGH 劫持摘除，mihomo 上游指向 AGH。

```text
App DNS
  -> TUN
  -> mihomo
  -> AGH :5591
  -> GeoIP / 上游
```

两条轨道都能独立提供 DNS 解析。自动切换失败或延迟只会留下次优拓扑，不应破坏
基本连通性。

## 健康门控

`controller.sh` 在 attach 与 detach 前都要求：

1. AGH 进程存在；
2. 向 `127.0.0.1:5591` 发出 UDP DNS 查询；
3. 收到与请求事务 ID 匹配的响应头。

任一条件失败都会拒绝动作并写 `events.log`。这避免在 AGH 已死时恢复劫持，造成
全机 DNS 黑洞。

## 状态机

| 状态 | 判定 |
|---|---|
| `NORMAL` | 没有检测到已知冲突 |
| `RISK_COEXIST` | VPN 与劫持同时存在 |
| `INCONSISTENT` | AGH 进程存在但劫持缺失 |
| `DOWN_PORT` | 劫持存在但端口未监听 |

`RISK_COEXIST` 是风险提示，不等同于完全不可用。若 DNS 路径实测正常，可以保持
观测；若需要最优拓扑，再启用 `auto`。

## 并发与单例

- guard 使用 pidfile 和 cmdline 校验维持单例；
- `controller.sh` 使用 flock，设备不支持 `-w` 时退回 mkdir 原子锁；
- WebUI 使用单飞任务锁，同一时间只运行一个动作；
- 30 秒自动刷新在任务运行期间跳过，不堆积 shell。

## 配置覆盖

guard 可读取 `run/config`，但只接受：

```text
# comment
NAME=safe-value
```

包含其他 shell 语法的配置会整份拒绝。默认关键参数包括：

| 参数 | 默认值 |
|---|---|
| `INTERVAL` | `90` 秒 |
| `IDLE_INTERVAL` | `300` 秒 |
| `HYSTERESIS` | `2` 轮 |
| `DNS_WARN_MS` | `800` ms |
| `FILTER_PROBE_TMO` | `2` 秒 |

修改生产参数前应先确认无 AGH / 无 Clash 降级路径和 DNS 黑洞保护仍然有效。
